30.0 Purpose and principles
The SLM at the heart of the orchestration is stateless by design: weights are
frozen during inference, models have no session memory between calls, and the
orchestrator owns every state transition.
This section defines the persistent memory layer that gives the system its
apparent continuity:
- the 90-day running IOC store,
- the audit handoff ledger between platforms,
- the long-term semantic recall layer,
- the per-run working state.
All four memory types are served by two engines:
PostgreSQL:
Durable orchestration memory using JSONB and pgvector.
SQLite:
File-based ephemeral working memory.
Design principles:
1. The model is a worker; the database IS the memory.
Models never talk to each other directly. The orchestrator reads memory,
stitches context, invokes a model, and writes every handoff back.
2. Postgres stores orchestration state, NOT raw telemetry.
Raw logs stay in OpenSearch, the SOC stack's own store. The handoffs table
uses payload_ref to point to large telemetry objects.
3. Sanitize before insert.
Nothing enters Postgres that has not passed the Section 20.2 pipeline and
the v11.5/v11.5.1 sanitization policy. The ledger is a dataset source via
corrections, so it must be clean by construction.
Sanitization metadata must be recorded: sanitizer_version,
sanitization_status, sanitization_action, regex_redaction_count,
entropy_redaction_count, redaction_manifest_sha256 where applicable, and
quarantine_reason if the payload was quarantined.
4. Retention is cron + partition drop.
Archives are written to CMR HDD first, then partitions are dropped.
5. No new heavy services.
A single Postgres instance is sufficient, typically around 100–200MB RAM.
6. Audit integrity is defense-in-depth.
Append-only role restrictions remain mandatory. Hash chaining or a separate
audit_chain table adds tamper evidence but does not replace least privilege.
30.1 Memory types and engine mapping
Operational memory:
Holds:
90-day IOC state, enrichment, alert links.
Engine:
PostgreSQL.
Handoff / audit memory:
Holds:
Every artifact passed between platforms and models.
Engine:
PostgreSQL.
Semantic recall memory:
Holds:
Embeddings of past cases, corrections, rules, and accepted proposals.
Engine:
pgvector inside PostgreSQL.
Working / ephemeral memory:
Holds:
Per-run quota ledger, harness task state, retries.
Engine:
SQLite.
Queue / backpressure memory [v11.5]:
Holds:
Sanitized alert references awaiting triage.
Engine:
PostgreSQL or SQLite.
Governance:
Section 35.
Wiki / externalized memory [v11.6]:
Holds:
Sanitized Markdown institutional knowledge generated by the SLM under
orchestrator control.
Engine:
Git-backed Markdown repository or local filesystem, referenced from the
handoff ledger.
Governance:
Section 38.
30.2 Postgres schema
Full DDL is maintained in Appendix K and Appendix P.
Core tables:
iocs:
90-day IOC state.
Partitioned by range on first_seen.
handoffs:
Append-only audit ledger of every artifact exchanged between components.
May be hash-chained per Section 37.
investigations:
Orchestrator state machine.
Includes status, autonomy_level, budget, and related orchestration fields.
corrections:
Human accept/fix/reject decisions.
Dataset intake source for gated retraining.
May be hash-chained per Section 37.
case_embeddings:
pgvector embeddings of past cases and corrections.
Top-k injection source for semantic recall.
May be time-partitioned per Section 36.
model_registry:
Signed adapters.
Includes role, hardware_profile, status, signer, cosigner, and checksum.
triage_queue [v11.5]:
Queue for decoupling alert ingestion from SLM inference.
Includes severity, payload_ref, status, attempts, lease_expires_at, and
last_heartbeat_at.
audit_chain [v11.5.1 recommended]:
Optional separate hash-chain table for sealed audit rows.
Preserves handoffs/corrections append-only model while adding tamper
evidence.
Selected indexes:
iocs(ioc, ioc_type, last_seen DESC)
handoffs(request_id, ts DESC)
handoffs(payload_sha256)
corrections(handoff_id, decision)
triage_queue(severity, enqueued_at) WHERE status = 'pending'
triage_queue(lease_expires_at) WHERE status = 'processing'
audit_chain(chain_seq)
audit_chain(table_name, row_id)
Vector index:
case_embeddings vector index:
Index type is benchmark-selected. Operational reality: for <10,000
cases, exact sequential scans are frequently faster and consume less
memory. For scaling, HNSW (for example m=16, ef_construction=64) is
strongly preferred over IVFFlat because it handles dynamic inserts
seamlessly without requiring periodic index rebuilds or maintenance
windows.
v11.5 addition:
case_embeddings may be range-partitioned by created_at. HNSW indexes
may be attached only to active partitions. Older partitions may drop
vector indexes while remaining queryable by sequential scan or metadata
indexes. See Section 36.
Append-only policy:
handoffs and corrections are append-only by schema.
The engine role receives only INSERT and SELECT privileges on these tables.
UPDATE and DELETE are not granted to the engine role.
Row deletion is performed via retention partition drop or explicit archive
and truncate during maintenance windows.
CI gate AMEND-12 verifies migration history contains no UPDATE/DELETE on
these tables.
v11.5.1 addition:
Hash-chain sealing must not grant the general engine role UPDATE rights
over handoffs or corrections. Preferred design is a separate audit_chain
table or a dedicated chain sealer role with tightly constrained rights.

intake
to_model
from_model
to_verifier
to_platform
payload_ref canonical contract [v11.4]:
For payloads larger than 1MB, or any payload not stored inline as JSONB,
the ledger must store payload_ref using a canonical URI scheme.
Approved URI schemes:
opensearch://<index>/doc/<id>
file:///archive/artifacts/<aa>/<bb>/<sha256><.ext>
s3://<bucket>/<key>
The ledger must also record:
payload_sha256
payload_size_bytes
payload_compression
payload_sanitizer_version
payload_sanitization_status
payload_sanitization_action
payload_retention_class
Hash-chain contract [v11.5, amended by v11.5.1]:
handoffs and corrections may be sealed through a hash chain.
The hash chain must be generated serially or by an asynchronous sealer.
Concurrent application inserts must not compute previous_hash directly if
multiple writers can append simultaneously.
Recommended default:
Separate audit_chain table.
See Section 37.
Wiki commit reference contract [v11.6]:
Wiki generation tasks that result in a Git commit must record the resulting
Git commit SHA in the handoff ledger as metadata.wiki_commit_ref or an
equivalent wiki_commit_ref field. This extends tamper evidence from
orchestration memory to externalized operational documentation.
The ledger is the primary audit source for post-incident review and the dataset
source for the corrections table.
The ledger must never contain raw telemetry.
30.4 Operational IOC memory
The IOC store uses a 90-day operational window.
Partitioning:
Monthly range partitions on first_seen.
Retention cron:
At day 1, archive partitions older than 90 days to CMR HDD.
Archive path:
/archive/iocs/YYYY-MM.jsonl.zst
After archive completion, DROP PARTITION.
Enrichment status lifecycle:
pending -> partial -> complete
pending -> partial -> quota_deferred
quota_deferred items are re-queued at quota reset per Section 26.2.
30.5 Semantic recall
Embedding model:
nomic-embed-text
768 dimensions
Served on the same inference card as the primary SLM worker where hardware
permits.
Embedding contract [v11.4, amended by v11.5.1]:
The embedding pipeline must pin:
embedding_model
embedding_model_revision_or_hash
embedding_dim
embedding_normalization
embedding_prefix_policy
If the selected embedding model uses task instruction prefixes, the
embedding writer and query path must enforce those prefixes.
For nomic-family embedding models, the lab must validate whether prefixes
such as document-side and query-side instruction strings are required for
retrieval quality.
Prefix injection must be implemented as a non-bypassable wrapper inside the
Python embedding service interface:
embed_document(text) prepends "search_document: "
embed_query(text) prepends "search_query: "
v11.5.1 addition:
Prefix injection must be idempotent. If text already contains the
required prefix, the wrapper must normalize it before prepending.
The wrapper must prevent double-prefixing such as:
search_document: search_document: <text>
search_query: search_query: <text>
If the embedding runtime cannot enforce the required prefix policy, the
embedding adapter must fail closed.
Sources embedded:
Accepted triage_summaries.
Accepted rule proposals.
Accepted corrections with decision = accept or fix.
Defense improvement proposals that passed CI.
Top-k injection:
On every orchestration request, the context stitcher queries
case_embeddings for the 3–5 most similar past cases within max_age_days.
The retrieved content is wrapped in:
<memory_context>
...
</memory_context>
The wrapped content is placed inside the user prompt and recorded in:
metadata.memory_context
Wrapped memory content remains inert to the model.
30.6 Multi-adapter registry
model_registry stores one row per signed adapter.
Each row includes:
role
adapter_sha256
signer
cosigner
hardware_profile
status
Status values:
canary
active
retired
Adapter routing config:
configs/adapter_routing.v11.3.yaml
Adapter routing maps:
task_type -> adapter_id
Models never hand off to each other directly.
The orchestrator writes to the shared ledger and composes the next prompt from
it.
Promotion is atomic:
Active adapter pointer swap.
Instant rollback to the previous signed adapter on any SLO regression.
30.7 Hygiene rules
Postgres stores orchestration state, not raw telemetry.
Sanitize before insert.
Section 20.2 sanitization is enforced at the adapter boundary.
v11.5 two-pass sanitization is enforced before orchestration memory insert.
v11.5.1 field-aware sanitization preserves high-value suspicious payloads
through quarantine-by-reference where appropriate.
v11.6 Wiki sanitization is enforced before externalized documentation commit.
Retention is cron + partition drop.
Archive to CMR HDD before partition drop.
No new heavy services.
OpenSearch retains raw telemetry and telemetry k-NN if needed.
Orchestration memory stays in Postgres so it remains available even when
OpenSearch is stopped during serialized training phases.
payload_ref artifacts must be integrity-checked and retention-classified.
Uncertain payloads must be quarantined, not silently inserted.
Alert ingestion must be decoupled from SLM inference per Section 35.
Queue stale recovery must be tested per Section 35.
Hash-chain sealing must be serialized per Section 37.
Wiki generation must be queued at low priority per Section 38.
30.8 Acceptance criteria
Postgres schema migration is reproducible and recorded in memory/migration/.
Append-only audit passes on handoffs and corrections.
90-day retention cron runs cleanly and produces archive artifacts on CMR HDD.
Embedding top-k injection is recorded in every relevant handoff row.
Adapter routing table is populated with only signed, co-signed adapters.
payload_ref integrity check passes for sample artifacts.
Embedding prefix contract check passes if prefixes are required.
Embedding prefix idempotency check passes.
Sanitization redaction and entropy checks pass for known secret/PII test
payloads.
Field-aware sanitization preserves approved IOC hashes and quarantines
high-value suspicious command-line payloads where policy requires.
Hash-chain verifier passes if hash chaining is enabled.
Hash-chain concurrency test passes if concurrent writers are enabled.
Queue backpressure behavior is tested if asynchronous intake is enabled.
Queue stale-job recovery is tested.
Partitioned vector index behavior is benchmarked if partitioning is enabled.
Wiki sanitization check passes if Wiki generation is enabled.
Wiki commit SHA is recorded in the handoff ledger if Wiki generation is
enabled.
